# 仕様 v0.7.3

## 目的

複数アカウントが関わる手動テストで、ログインの切り替えと画面準備の負担を減らす。macOSのデスクトップアプリとして提供する。

## セッションとタブ

- タブとセッションを別管理し、各タブに1つのセッションを割り当てる。
- 同一セッションはCookie・サイトストレージを共有し、異なるセッションは分離する。
- セッションはUUIDで識別し、表示名・色・保存の有無を持つ。表示名はログイン中のアカウントを保証しない。
- 保存セッションのpartitionは再起動後も固定。一時セッションは起動ごとの識別子を使う。
- 最低1つのセッションと、通常操作時に最低1つのタブを維持する。
- タブの追加・選択・終了、URL入力、戻る・進む・再読み込みを提供する。
- セッション名のクリックで、そのセッションの空タブを開く。
- 「別セッション」で現在のURLを別のタブとして開く。フォームやページ状態は移さない。
- タブのセッションを直接書き換える操作は設けず、新規タブで開く。

## タブの並び替えと左右分割

- 6px以上のドラッグで移動を開始し、タブ列の挿入位置へドロップすると順序を更新する。
- タブのID・セッション・WebContentsを維持し、ページの再読み込みは行わない。
- ページ領域の左/右へタブをドロップすると、左右均等の2分割にする。最低2タブを必要とする。
- 選択中のタブだけを青い背景と上線で強調する。分割中の位置はLEFT/RIGHTバッジで示し、非選択の表示中タブには選択色を付けない。
- タイトル更新・ドラッグ候補待機・遅延した状態通知があっても、タブ・ペイン・URL欄の選択対象を一致させる。
- 分割中の反対側へ同じタブを移動すると左右を交換する。第3のタブをドロップすると対象側だけを置き換える。
- タブ列で非表示のタブを選択、または新規タブを作成すると選択中ペインを置き換える。
- URL・履歴・DevToolsは選択中ペインのタブに適用し、ページのフォーカスと見出しのクリックで選択を更新する。
- 分割中のタブを閉じると分割を解除し、もう一方を全体表示する。非表示タブを閉じても分割配置は維持する。
- 分割/解除ボタンを設ける。分割解除時は選択中タブを全体表示する。
- ドラッグ中のEsc・ポインターキャンセル・ウィンドウのフォーカス喪失で移動を取り消す。
- キーボードではフォーカスしたタブをOption+Shift+左右キーで並び替える。
- 作業セットは変更後のタブ順を保存する。分割状態は保存しない。
- 初版は左右2ペインのみ。サイズ比の変更・上下/4分割・別ウィンドウへの切り離しは範囲外。

## 管理

- セッションの作成、名前・色の変更、初期化、削除に対応する。
- 保存 / 一時の種類は作成後に変更しない。変更したい場合は別のセッションを作る。
- 初期化・削除はネイティブダイアログで確認後、対象のタブとポップアップを閉じて処理する。
- Cookie・サイトデータ・キャッシュを削除する。HTTP認証キャッシュも明示的に消去する。
- 最後のセッションは削除しない。
- 削除したセッションは保存済み作業セットからも除く。

## アドレス欄と右クリック

- URLではない入力はGoogle検索URLに変換し、現在のタブ・セッションで開く。
- ドメインはHTTPS、localhostやIPアドレスはHTTPを補完する。明示されたHTTP/HTTPSを優先し、危険なスキームは検索に回さず拒否する。
- `site:example.com` などの検索演算子は検索語として扱う。
- 保存済みの作業セットやタブ作成のURL検証には検索補完を使わない。
- 右クリックは対象ページに応じて編集・リンク・画像・動画/音声・ナビゲーション・検索・保存・印刷・検証メニューを出す。操作はクリック元のWebContentsに適用し、リンク・画像・選択文検索は同じセッションのタブで開く。
- 画像・リンク先・保存可能な動画/音声を、ネイティブの保存先選択を通して保存する。HTTP/HTTPSのURLに加え、画像はBlob・Data形式の保存も対象とする。
- 任意のfile/javascript等のスキームは保存対象にしない。選択文検索は利用者が項目を選んだ場合だけGoogle検索を実行する。
- ページ内検索窓は元のページに固定し、検索件数・次/前の一致を表示する。Cmd+Fで開き、検索窓はEnter・Shift+Enter・Escを受け付ける。
- ページ保存はMHTML形式、印刷はサイレント印刷を行わずOSのダイアログを使う。Cmd+Pでも印刷を開く。
- 保存・ダウンロード・印刷の失敗は表示する。利用者によるキャンセルはエラー表示しない。
- 管理画面のURL入力欄にも編集メニューを提供する。

## DevTools

- 選択中のタブのChromium DevToolsを別ウィンドウで開く。
- 複数タブで同時に利用でき、ウィンドウタイトルにセッション名を表示する。
- DevToolsを閉じても対象タブを閉じない。

## 作業セット

- セット名と、タブごとのセッションID・URL・並び順を保存する。
- 保存時に新規追加と既存セットへの上書きを選択できる。新規追加では同名でも別セットとし、上書きは確認後に同じIDのセットを置き換える。
- 復元前に確認し、現在のタブとポップアップを閉じて保存構成に置き換える。
- 保存セッションのログイン状態は維持する。一時セッションは古いデータを消去して新しいpartitionで開く。
- 復元後は先頭タブを選択する。
- タブが0件になったセットは一覧に残し、復元を無効にする。
- タブ構成は自動保存しない。再起動直後は先頭セッションの空タブを表示する。

## ポップアップ・ダウンロード・権限

- 新規ウィンドウ要求は、元のセッションを引き継ぐ子ウィンドウで開く。OAuth等のopener関係とPOSTを維持するため、通常のtarget=_blankリンクも初期版では子ウィンドウ扱いとする。
- 子ウィンドウもNode.js無効・コンテキスト分離・サンドボックス有効とする。
- ダウンロードにはElectron標準の保存先選択ダイアログを使用する。
- カメラ・マイク等の権限要求は確認ダイアログを表示し、未対応の権限は拒否する。バックグラウンドの権限チェックは許可しない。
- HTTP / HTTPS と空ページ以外のトップレベル遷移は拒否する。独自プロトコルや外部アプリの起動は行わない。

## WebAuthnの非対応ポリシー

未署名ビルドではパスキー・セキュリティキー認証に対応しない。トップレベルページと認証ポップアップのWebAuthn要求を速やかに `NotAllowedError` で終了し、「別の方法を試す」等から代替認証を選ぶよう案内する。conditional autofillのバックグラウンド要求では案内を表示しない。パスキーが必須のサイトは利用できない。認証情報の生成・偽装・外部ブラウザからの移送は行わない。

## 安全性

- 任意サイトには管理用IPC APIを渡さない。サイト用preloadは非対応認証の終了と案内通知のみを行う。
- 管理UI専用のpreloadから必要な操作だけを公開し、メイン側で送信元と入力を検証する。
- 証明書エラーを無視しない。Webセキュリティを無効化しない。
- 設定は一時ファイルからrenameして更新する。不正な設定ファイルは自動上書きせず、エラーを表示して終了する。
- 一時セッションはブラウザの通常のディスク永続化を行わない。ダウンロードしたファイルやOSの記録まで消去する匿名化機能ではない。

## 受け入れ条件

1. 異なる4セッションで同一サイトへログインできる。
2. 1セッションのCookie・Local Storageが他のセッションに現れない。
3. 同じセッションの複数タブではCookie・Local Storageを共有する。
4. 保存セッションの認証状態は有効期限内なら再起動後も利用できる。
5. 一時セッションは再起動後に状態を引き継がない。
6. 初期化したセッション以外の保存データは維持される。
7. 各タブのDevToolsを開ける。
8. 作業セットからセッション・URL・順序を復元できる。
9. 子ウィンドウは元のセッションを使用し、アプリ管理APIへアクセスできない。

実際の業務サイトでの認証、参加承認、メッセージ送受信などは別途受け入れ確認する。

## Ver 0.4.0：セッション連携HTTPクライアント

- Web / APIの2種類のタブを同じタブ列で管理し、並び替え・左右分割・作業セットで一緒に扱う。
- APIタブは作成時のセッションに固定する。別セッションでは定義を複製して開く。
- メソッド、明示的なHTTP(S) URL、クエリ、カスタムヘッダー、JSON・テキスト本文を編集できる。GET / HEADは本文を送らない。
- 認証はCookie共有・なし・Bearerから選択する。Cookie共有時のみブラウザのCookieを送受信する。HttpOnlyの値は画面から読み取らず、ElectronのSessionで扱う。
- ステータス・時間・受信バイト数・ヘッダー・本文を表示する。JSON整形、Raw、本文コピーに対応する。HTMLは実行しない。
- 保存リクエストはセッションごとに管理し、追加・更新・読み込み・削除できる。各タブの履歴は20件。API定義を作業セットにも保存する。
- 保存・複製・履歴にBearer値と認証系ヘッダーを残さない。URL・クエリ・本文は除外対象外で、明示保存時はローカルのJSONファイルに含める。
- 定義・履歴を開くだけでは送信しない。送信中の中止、タイムアウト（既定30秒、1〜120秒）、タブ終了時の中止に対応する。
- リダイレクトは追跡しない。本文1 MiB、応答5 MiBの上限。バイナリの本文表示、OAuth・Basic認証・multipart・ファイル添付・環境変数・コレクション・cURLインポート・自動テストは範囲外。

追加受け入れ条件：

1. Web画面でログインした2アカウントのHttpOnly Cookieを、対応するAPIタブだけで送信できる。
2. 通信中に別タブを選んでもセッションや応答先が混ざらない。
3. 認証なし・BearerではCookieを送らず、Set-Cookieもブラウザへ反映しない。
4. APIのSet-CookieはCookie共有時だけ該当Webセッションに反映される。
5. 保存・再起動・作業セット復元で定義を読み込めるが、自動送信せず、Bearer・応答・履歴は復元しない。
6. Web画面とAPI画面を同時に表示でき、API側から管理用APIや任意サイトへ遷移できない。

## Ver 0.5.0：Mac版の仕上げ

1. CLIタブを追加し、ローカルの対話シェル・リサイズ・中断・停止・再起動・起動フォルダ選択を提供する。タブ列、分割、作業セットでWeb/APIと一緒に管理する。
2. CLIのセッション名は整理用で、OS権限やファイル、環境を分離しない。ブラウザのCookieは渡さない。
3. CLIタブの保存は起動フォルダのみ。復元後は手動起動し、コマンド・出力・実行中プロセスを復元しない。タブ・ウィンドウ・アプリの終了時にCLIの子孫プロセスを停止する。
4. アプリとCLIの子孫のRSS合計の目安を表示し、約3秒ごとに更新する。共有ページの重複を含むことを明示する。
5. 警告値は既定2048 MiB、256〜65536 MiBで指定、0で無効。超過時の警告を閉じたら、90%未満に下がるまで再通知しない。自動でページやプロセスを終了しない。
6. 構成保存は新規追加/既存への上書きを選択でき、上書き時に確認する。
7. 起動時と手動でGitHub Releasesの最新安定版を確認する。利用者は起動時チェックを無効化できる。利用中のCookieを送らない。公開なし・失敗・最新版・更新ありを区別する。
8. 更新があれば公開ページへ案内する。自動インストールは含まない。リリースの公開は別途行う。
9. 起動中のアプリ、Electron、Chromiumの実際の版数を画面とアプリメニューから確認できる。
10. Mac版を優先する。Windows対応は将来の低優先度項目とする。

## Ver 0.6.0：承認済みの追加範囲（1・2・6）

- JWT候補はCookie名を固定せず、値の形式から検出する。セッション・サイト・Cookieのドメイン/パスを区別して選択できる。JWT以外のCookie表示と手入力も提供する。
- コピー時は対象Cookieの現在値を取得する。値のみ/name=valueの形式を用意する。JWTのclaimは未検証の参考表示とし、有効期限とCookie期限を区別する。
- 手入力はブラウザのCookieを変更しない。既定は起動中のみ、明示選択した場合だけOSの鍵で暗号化保存する。
- 応答検索は記録開始後のJSON・テキスト本文を対象とし、タブ/セッションを横断する。結果には元のタブ・リクエスト・時刻・ステータス・抜粋を表示する。全文表示・最初の一致箇所への移動・選択部分のコピー・元タブへの移動ができる。
- 記録はメモリ内で1件1 MiB・合計20 MiB・300件、検索結果は100件まで。検索・表示で再送信しない。WebSocket等は初版の対象外。
- Cookie暗号化と手入力値のsafeStorageを分け、OSごとの鍵管理を共通API経由で利用する。暗号化不能時は既存データを維持し、ブラウザの保存を停止する。
- 既存Cookieの暗号化移行でログイン・属性・サイトストレージを維持する。移行後に暗号化非対応版を同じデータ保存先で使うことは非対応。
- 環境複製・帯への環境ラベル追加・操作記録のファイル出力は今回の範囲に含めない。

## Ver 0.7.0：通常のブラウザメニュー

- ツールバーの右端にネイティブの「⋮」メニューを置く。履歴・ブックマークと最近の項目、タブ追加、ズーム、検索、保存、印刷、全画面、設定、更新確認、既存のテスト用ツールを提供する。
- Webページは「☆」/Cmd+Dでブックマーク登録。名前・URL・セッションを編集でき、管理画面で検索・削除・直前の削除の取り消しを提供する。
- WebのトップレベルHTTP(S)遷移・SPAのURL変更・ポップアップを、URL・タイトル・時刻・セッションとともに記録する。API/CLI・管理画面・リクエスト本文は対象外。
- 専用ウィンドウで履歴・ブックマークをタイトル/URL検索し、セッションで絞り込める。項目は元のセッションの新しいタブに開き、Cookieを別セッションへ移さない。
- 一時セッションの履歴はメモリ内だけとする。ブックマークは明示的な保存操作として、一時セッション分も永続化する。
- 履歴・ブックマーク各2000件、保存データ4 MiBを上限とし、超過時は古い履歴を削除する。OSの鍵で暗号化し、利用不能時はメモリ内だけで動作する。復号不能な既存ファイルを上書きしない。
- 履歴は全体/セッション単位で消去でき、Cookie・ブックマークを消さない。セッション初期化は履歴を消去し、セッション削除は該当ブックマークも削除する。
- ネイティブメニューがWebContentsViewに隠れず、最小幅960pxでもメニューボタンに到達できる。
- 他ブラウザからのインポート、同期、ブックマークのフォルダ、ダウンロード管理、拡張機能は対象外。

## Ver 0.7.1：URL選択とAPI入力の切り替え

- ブラウザのURL欄は、初回クリック・Tab・Cmd+Lで全文を選択する。フォーカス後のクリックはカーソル移動、ドラッグは部分選択として扱う。
- APIのメソッドがPOSTへ変わった時は「本文」、GET / HEADへ変わった時は「クエリ」を選択する。GET / HEADの本文タブは非表示とする。
- メソッドを往復してもクエリ・本文・本文形式を保持する。POSTのクエリは既存のタブから編集でき、クエリを付けたPOST送信も維持する。
- 入力・通信結果・状態通知では手動選択した設定タブを維持する。保存定義や履歴を開いてメソッドが変わった時にも表示を合わせる。

## Ver 0.7.2：WebページのPDF保存

- 「⋮」とWebページの右クリックから「PDFとして保存…」を選び、保存ダイアログで名前と保存先を指定する。Webタブ・認証ポップアップを対象とし、API/CLI・管理画面は対象外。
- 操作元のWebContentsを直接 `printToPDF` し、保存のために別セッションでURLを再取得しない。基本はA4・背景ありで、サイトの印刷用CSSと用紙指定を優先する。
- 保存元のタブを閉じた場合は中止し、URLが変わった場合は再操作を案内する。別タブを選んだだけなら元のページを保存する。
- 完成したPDFを同じ保存先ディレクトリの一時ファイルから原子的に置き換え、0600で保存する。キャンセルや生成失敗では既存ファイルを変えない。
- 同じページでの重複実行を避け、終了時に一時ファイルと実行中フラグを片付ける。従来の印刷・MHTML保存は引き続き利用できる。

## Ver 0.7.3：メインプロセスの責務整理

機能・操作・保存形式を保ったまま、メインプロセスのタブ／ビュー、セッション、作業セット、操作受付、IPC認可、メニュー等のネイティブ操作を分離する。暗号化や平文トークンの保持期間を変える対応は含めない。管理画面rendererの構造変更や、テストファイル全体の分割も今回の対象外。
