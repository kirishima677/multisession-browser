# 仕様 v0.1.1

## 目的

複数アカウントが関わる手動テストで、ログインの切り替えと画面準備の負担を減らす。macOSのデスクトップアプリとして提供する。

## セッションとタブ

- タブとセッションを別管理し、各タブに1つのセッションを割り当てる。
- 同一セッションはCookie・サイトストレージを共有し、異なるセッションは分離する。
- セッションはUUIDで識別し、表示名・色・保存の有無を持つ。表示名はログイン中のアカウントを保証しない。
- 保存セッションのpartitionは再起動後も固定。一時セッションは起動ごとの識別子を使う。
- 最低1つのセッションと、通常操作時に最低1つのタブを維持する。
- タブの追加・選択・終了、URL入力、戻る・進む・再読み込みを提供する。
- セッション名のクリックで、そのセッションの空タブを開く。
- 「別セッション」で現在のURLを別のタブとして開く。フォームやページ状態は移さない。
- タブのセッションを直接書き換える操作は設けず、新規タブで開く。

## 管理

- セッションの作成、名前・色の変更、初期化、削除に対応する。
- 保存 / 一時の種類は作成後に変更しない。変更したい場合は別のセッションを作る。
- 初期化・削除はネイティブダイアログで確認後、対象のタブとポップアップを閉じて処理する。
- Cookie・サイトデータ・キャッシュを削除する。HTTP認証キャッシュも明示的に消去する。
- 最後のセッションは削除しない。
- 削除したセッションは保存済み作業セットからも除く。

## アドレス欄と右クリック

- URLではない入力はGoogle検索URLに変換し、現在のタブ・セッションで開く。
- ドメインはHTTPS、localhostやIPアドレスはHTTPを補完する。明示されたHTTP/HTTPSを優先し、危険なスキームは検索に回さず拒否する。
- `site:example.com` などの検索演算子は検索語として扱う。
- 保存済みの作業セットやタブ作成のURL検証には検索補完を使わない。
- 右クリックは対象ページに応じて編集・リンク・画像・ナビゲーション・検証メニューを出す。操作はクリック元のWebContentsに適用し、リンクは同じセッションで開く。
- 管理画面のURL入力欄にも編集メニューを提供する。

## DevTools

- 選択中のタブのChromium DevToolsを別ウィンドウで開く。
- 複数タブで同時に利用でき、ウィンドウタイトルにセッション名を表示する。
- DevToolsを閉じても対象タブを閉じない。

## 作業セット

- セット名と、タブごとのセッションID・URL・並び順を保存する。
- 同名セットの保存は追加として扱う。上書きは行わず、不要なセットを削除する。
- 復元前に確認し、現在のタブとポップアップを閉じて保存構成に置き換える。
- 保存セッションのログイン状態は維持する。一時セッションは古いデータを消去して新しいpartitionで開く。
- 復元後は先頭タブを選択する。
- タブが0件になったセットは一覧に残し、復元を無効にする。
- タブ構成は自動保存しない。再起動直後は先頭セッションの空タブを表示する。

## ポップアップ・ダウンロード・権限

- 新規ウィンドウ要求は、元のセッションを引き継ぐ子ウィンドウで開く。OAuth等のopener関係とPOSTを維持するため、通常のtarget=_blankリンクも初期版では子ウィンドウ扱いとする。
- 子ウィンドウもNode.js無効・コンテキスト分離・サンドボックス有効とする。
- ダウンロードにはElectron標準の保存先選択ダイアログを使用する。
- カメラ・マイク等の権限要求は確認ダイアログを表示し、未対応の権限は拒否する。バックグラウンドの権限チェックは許可しない。
- HTTP / HTTPS と空ページ以外のトップレベル遷移は拒否する。独自プロトコルや外部アプリの起動は行わない。

## WebAuthnの非対応ポリシー

未署名ビルドではパスキー・セキュリティキー認証に対応しない。トップレベルページと認証ポップアップのWebAuthn要求を速やかに `NotAllowedError` で終了し、「別の方法を試す」等から代替認証を選ぶよう案内する。conditional autofillのバックグラウンド要求では案内を表示しない。パスキーが必須のサイトは利用できない。認証情報の生成・偽装・外部ブラウザからの移送は行わない。

## 安全性

- 任意サイトには管理用IPC APIを渡さない。サイト用preloadは非対応認証の終了と案内通知のみを行う。
- 管理UI専用のpreloadから必要な操作だけを公開し、メイン側で送信元と入力を検証する。
- 証明書エラーを無視しない。Webセキュリティを無効化しない。
- 設定は一時ファイルからrenameして更新する。不正な設定ファイルは自動上書きせず、エラーを表示して終了する。
- 一時セッションはブラウザの通常のディスク永続化を行わない。ダウンロードしたファイルやOSの記録まで消去する匿名化機能ではない。

## 受け入れ条件

1. 異なる4セッションで同一サイトへログインできる。
2. 1セッションのCookie・Local Storageが他のセッションに現れない。
3. 同じセッションの複数タブではCookie・Local Storageを共有する。
4. 保存セッションの認証状態は有効期限内なら再起動後も利用できる。
5. 一時セッションは再起動後に状態を引き継がない。
6. 初期化したセッション以外の保存データは維持される。
7. 各タブのDevToolsを開ける。
8. 作業セットからセッション・URL・順序を復元できる。
9. 子ウィンドウは元のセッションを使用し、アプリ管理APIへアクセスできない。

実際の業務サイトでの認証、参加承認、メッセージ送受信などは別途受け入れ確認する。
