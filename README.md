# Multisession Browser

タブごとにセッションを割り当て、同じサイトを複数アカウントで同時に操作する、macOS向けのテスト用ブラウザです。Electron / Chromiumを使用しています。

## できること

- **タブのドラッグ操作**：タブ列へドロップして並び替え。ページ領域の左右へドロップして2分割表示。
- **独立したセッション**：異なるセッションのCookie・Local Storage・IndexedDBなどを分離。同じセッションのタブ間では共有します。
- **保存 / 一時セッション**：保存セッションは次回起動時も利用。一時セッションはアプリ終了後に状態を引き継ぎません。
- **タブごとのDevTools**：Elements・Console・Network・Applicationなどを別ウィンドウで利用できます。
- **CLIタブ**：Macのログインシェルを対話操作。Web/APIタブと一緒に並べ替え・左右分割できます。
- **メモリと更新確認**：使用量の目安・しきい値警告、バージョン表示、起動時の更新チェック。
- **APIタブ**：セッションのログイン状態でHTTPリクエストを送り、Web画面と左右に並べて確認できます。
- **作業セット**：WebタブのURL・APIのリクエスト定義・並び順・セッションをまとめて保存、復元できます。
- **セッション管理**：名前・色の変更、保存データの初期化、セッションの削除。
- **アドレス欄から検索**：URL以外の語句はGoogle検索。ドメイン名はHTTPS、`localhost`やIPアドレスはHTTPで開きます。明示した `http://` / `https://` を優先します。
- **右クリックメニュー**：画像・リンク先の保存、画像を新しいタブで開く、選択文の検索、書式なし貼り付け、ページ内検索・保存・印刷など。
- **認証ポップアップ**：開いた元のセッションを引き継ぎます。

最初は `A社 a1`・`A社 a2`・`B社 b`・`運営 u` の4つの保存セッションを用意します。これらは表示用のラベルであり、対象サイトのアカウント作成や自動ログインは行いません。

## 開発版を起動する

macOS 13以降、Node.js 22以降とnpmを使用します。macOSのApple Siliconを主な検証対象としています。Windows対応は将来の低優先度項目です。

```sh
npm ci
npm start
```

初回起動時はElectron本体をダウンロードするため、ネットワーク接続が必要です。

1. 左のセッション名をクリックし、タブを開きます。
2. URL欄にテスト対象のURLを入力し、そのセッションでログインします。
3. 別のセッションのタブで、別アカウントにログインします。
4. `DevTools` で選択中のタブの通信・ログ・Cookieを確認します。
5. 「構成を保存」で、次回利用するタブ構成を保存します。

ドメイン名だけならHTTPS、`localhost:3000`・IPアドレスならHTTPとして開きます。日本語や単語、スペースを含む入力はGoogle検索します。検索には選択中のセッションを使用し、履歴一覧や検索候補の通信は実装していません。

## CLI・メモリ・更新確認（Ver 0.5.0）

### CLIタブ

「＋ CLI」または `⌘⌥J` でセッションを選ぶと、Macのログインシェル（`$SHELL`、未設定時は`/bin/zsh`）を開きます。node-ptyとxterm.jsを使った対話型ターミナルで、Ctrl+C・矢印キー・色表示・サイズ変更に対応します。Web/APIタブと同じタブ列で管理し、並び替え・左右分割できます。

CLIのセッション名は整理用のラベルです。**CLIはこのMacのユーザー権限で動き、ブラウザのCookieやセッションの分離は引き継ぎません。** CLI同士も同じユーザーのファイル・環境を扱います。

- 起動フォルダはホームです。シェルを「停止」し、「起動フォルダ」から別のディレクトリを選んで再起動できます。
- 「停止」・タブを閉じる・構成復元・ウィンドウ終了・アプリ終了時に、ターミナルとその時点の子孫プロセスを終了します。意図的に切り離したデーモンや別アプリのプロセスは管理対象外です。
- 作業セットに保存するのはCLIタブの種類・セッション・起動フォルダです。入力したコマンド、出力、実行中プロセス、`cd`後のディレクトリは保存しません。**構成から復元したCLIは未起動で、「シェルを起動」を押して再開します。** シェル自身の履歴・設定ファイルは通常どおりシェルが管理します。
- 表示のスクロールバックは3000行。アプリ内部の再表示用出力バッファにも上限を設け、大量出力時は受信側に合わせてPTYを一時停止します。
- CLI画面にブラウザ管理API・Node.jsを渡さず、WebページやAPI応答からターミナル操作はできません。リモートHTMLや拡張機能をCLI画面へ読み込みません。

### メモリ表示・警告・アプリのバージョン

画面下部にメモリ使用量の目安を表示します。Electronの各プロセスに加え、CLIシェルとその子孫プロセスのRSSを約3秒ごとに合計します。共有メモリの重複を含み、macOSのアクティビティモニタの「メモリ」とは測定方法が異なります。OS全体の空きメモリやメモリプレッシャーの表示ではありません。

初期の警告値は2048 MiBです。超えると下部表示の色が変わり、サイドバーに警告を表示します。警告は閉じることができ、一度閉じると設定値の90%未満に下がるまで再通知しません。自動でタブやプロセスを閉じることはありません。

上部の `v0.5.0` または下部のメモリ表示をクリックすると「アプリ情報・設定」を開きます。**起動中の実際のアプリの版数**、Electron / Chromiumの版数、メモリ使用量を確認できます。警告値は256〜65536 MiB、0で無効。設定は次回起動時も保持します。Macのアプリメニューからも同じ画面を開けます。

### 構成の新規保存・上書き

「構成を保存」で「新規追加」「既存の構成を上書き」を選びます。上書き先を選び、名前も変更できます。確認後、既存の作業セットIDを維持してタブ構成を置き換えます。同名の新規保存は別の構成として追加します。

### 起動時のアップデート確認

起動時に `kirishima677/multisession-browser` のGitHub Releases APIへアクセスし、最新の安定版タグと起動中のアプリの版数を比較します。Webのログイン情報やCookieは送信しません。新しい版があればサイドバーに案内し、「リリースを開く」から既定ブラウザで公開ページを開きます。アプリ情報画面には手動の確認ボタンと、起動時チェックのオン/オフ設定があります。

この版は**更新確認と公開ページの案内**に対応します。ダウンロード・アプリの置き換え・自動インストールは行いません。公開リリースがない場合と通信に失敗した場合を区別して表示し、失敗してもブラウザ操作を継続できます。

2026-11-24の実装時点ではGitHub Releasesに公開済みリリースはありません。今後は版数を上げてMacアプリをビルドし、`v0.5.1`のような安定版タグとアプリをGitHub Releasesへ公開すると、以前のアプリから検知できます。コードのpushやタグ作成だけでは更新として通知しません。リリースの公開作業は実施していません。

開発・テストでは `MSB_UPDATE_URL` で同形式のJSON配信先を変更できます。HTTPS、またはローカルのHTTPのみ受け付けます。外部ページへ開ける更新先はこのリポジトリのGitHub Releasesに限定します。

## APIクライアント（Ver 0.4.0）

1. URL欄の横の「＋ API」または `⌘⌥T` で、新しいAPIタブのセッションを選びます。
2. `http://` / `https://` のURLとHTTPメソッドを指定します。
3. 「クエリ」「ヘッダー」「本文」「認証」で設定し、「送信」または `⌘Enter` で実行します。
4. ステータス・所要時間・受信サイズ・レスポンスの本文とヘッダーを確認します。JSONは整形表示でき、Raw表示・本文のコピーにも対応します。

**セッションはAPIタブを作る時に固定します。** 別のWebタブを選択しても、送信先や認証元は変わりません。Webタブと同じように並び替え・左右分割できるため、操作画面とAPIの結果を並べられます。

| 認証方法 | 動作 |
|---|---|
| ブラウザのCookieを使用 | 選択セッションのCookie（HttpOnlyを含む）を使用。応答のSet-Cookieも同じセッションに反映 |
| 認証なし | Cookieと自動認証を送らず、Set-Cookieをブラウザに反映しない |
| Bearer | 入力したBearerを送信。Cookieと自動認証を送らず、Set-Cookieをブラウザに反映しない |

- メソッドはGET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS。クエリは1行に `key=value`、ヘッダーは1行に `Name: value` で入力します。クエリはURLエンコードします。
- 本文はJSON・テキスト・なし。GET / HEADでは本文を送りません。JSONの形式は送信前に検証します。
- Cookie・Authorization・Host等の管理ヘッダーは直接指定せず、認証欄を使います。CSRFトークン・Origin等、対象APIに必要な値はカスタムヘッダーへ明示してください。トークンの自動取得・CSRFの回避は行いません。
- 名前を付けて「保存」すると、そのセッションのリクエスト一覧に追加します。同じ定義で再度保存すると上書きします。「開く」で読み込み、「削除」で消せます。履歴は各APIタブの直近20件で、アプリ終了時に破棄します。
- 「別タブへ複製」または上部の「別セッション」から、リクエストを別セッションで試せます。複製元の認証情報は引き継ぎません。
- API定義は作業セットにも保存します。**保存定義・履歴・作業セットを開いても自動送信しません。** 実行には「送信」が必要です。レスポンスは永続化しません。
- Bearer値とCookie・Authorization・token・secret・API keyを含む名前のヘッダーは、保存・履歴復元・複製から除きます。URL・クエリ・本文は保存対象です。これらに直接記入した機密値は除去されません。
- タイムアウトは既定30秒、1〜120秒で指定でき、送信中は中止できます。タブを閉じた場合も中止します。
- 本文は1 MiB、レスポンスは5 MiBまで。大きい応答は上限で受信を中止して表示します。リダイレクトは自動追跡せず、30xとLocationを表示します。バイナリはメタデータのみ表示し、HTMLをページとして実行しません。本文のテキスト表示はUTF-8です。

この版ではOAuthフロー、Basic認証、multipart・ファイル添付、cURLのインポート、環境変数、コレクション、WebSocket、自動テストの実行には対応しません。

## 右クリックの追加操作（Ver 0.3.0）

右クリックした場所に応じて項目が変わります。

| 場所 | 主な操作 |
|---|---|
| 画像 | 別名で保存、コピー、URLコピー、同じセッションの新しいタブで開く |
| リンク | 同じセッションの新しいタブで開く、リンク先を別名で保存、URLコピー |
| 選択した文章 | コピー、Google検索（同じセッションの新しいタブ） |
| 入力欄 | 元に戻す、やり直す、切り取り、貼り付け、書式なし貼り付け、削除、全選択 |
| 保存可能な動画・音声 | 別名で保存、URLコピー |
| ページ全体 | 戻る・進む・再読み込み、ページ内検索、ページ保存、印刷、要素の検証 |

- 保存時は保存先を選択します。ダウンロードは右クリックしたタブのセッションを使用するため、ログインが必要な画像にも同じ認証状態でアクセスします。
- 画像保存はHTTP/HTTPSに加え、Blob・Data形式にも対応し、元データの形式で保存します。画像を新しいタブで開く操作はHTTP/HTTPSの画像に対応します。
- 動画・音声の保存はChromiumが保存可能と判断するリソースが対象です。一部のストリーミング・DRMコンテンツは対象外です。
- ページ内検索は `⌘F` でも開けます。検索窓でEnterが次、Shift+Enterが前、Escで閉じます。検索窓は開いた元のページを対象にし、別のタブを選んでも対象は変わりません。
- ページ保存は画像等をまとめた1ファイルのWebアーカイブ（`.mhtml`）です。対応ブラウザで開けます。
- 印刷は `⌘P` でも開けます。Macの印刷ダイアログで、印刷またはPDFとしての保存を選択してください。
- 翻訳・画像の逆検索・動画の再生操作・ブラウザ拡張による項目など、一般ブラウザの全項目を再現するものではありません。

## タブの並び替え・左右分割（Ver 0.2.0）

- タブを左右にドラッグし、タブ列の挿入位置にドロップすると並び替えます。
- 2つ以上のタブがある状態で、タブをページ領域までドラッグすると左右のドロップ先が表示されます。希望する側にドロップすると2分割します。
- 「分割」ボタンからも、選択中のタブと別のタブを並べられます。「解除」で選択中のタブの全体表示に戻ります。
- 青い背景と上線のタブが選択中です。分割で表示している位置はタブの `LEFT / RIGHT` バッジで区別します。
- 分割したページやその上の見出しをクリックすると、URL欄・戻る/進む・再読み込み・DevToolsの対象を切り替えます。
- 表示中のタブを反対側へドロップすると左右を交換します。別のタブをドロップすると、その側だけを置き換えます。
- 分割中に非表示のタブを選択・新規作成すると、選択中のペインだけを置き換えます。外れたタブもタブ列に残ります。
- 表示中の片側を閉じると、残ったペインを全体表示します。
- `Esc` でドラッグをキャンセルできます。タブにフォーカスして `⌥⇧←` / `⌥⇧→` でも並び替えできます。

並び替え・分割はページを再読み込みせず、フォームの入力やセッションを保持します。作業セットには並び替え後のタブ順を保存します。**分割配置は保存しません。** 初版の分割は左右均等の2ペインです。上下分割・4分割・境界のサイズ変更・別ウィンドウへの切り離しは含みません。

## Macのアプリを作る

```sh
# 現在のMacと同じCPU向けの .app を生成
npm run pack:mac

# ZIPとDMGを生成
npm run dist:mac
```

Apple Siliconでは `dist/mac-arm64/Multisession Browser.app`、Intelでは通常 `dist/mac/Multisession Browser.app` に生成します。

今回生成したVer 0.5.0は、旧版を残すため `dist/v0.5.0/mac-arm64/Multisession Browser.app` に配置しています。利用中の旧版を `⌘Q` で終了してから開いてください。保存セッションと作業セットは引き続き使用します。

別のCPUを指定する場合：

```sh
npm run dist:mac -- --arm64
npm run dist:mac -- --x64
```

初期設定はDeveloper ID署名・公証なしのローカル開発向けです。配布用の署名・公証は別途設定してください。Intel向けの実機動作は未検証です。

## 保存するデータ

標準の保存先は `~/Library/Application Support/Multisession Browser/` です。

- `workspace.json`：セッションの名前・色・種類、保存APIリクエスト、作業セットのURL・API定義・CLIの起動フォルダ・タブ順序、メモリ警告・更新確認の設定。ファイルのアクセス権は所有者のみ（0600）で、内容は暗号化しません。
- `Partitions/` など：Electronが管理する保存セッションのデータ。

作業セットは画面のスナップショットではありません。Webページの入力途中の内容、スクロール位置、通信履歴、ページ内の一時的な状態は復元しません。APIタブは入力した定義を復元しますが、Bearer等の除外対象と実行結果は復元しません。復元は現在のタブとポップアップを閉じて行い、保存セッションの状態は維持、一時セッションの状態はリセットします。CLIタブは復元後に手動でシェルを起動します。セッションを削除すると、作業セットからもそのセッションのタブを除きます。

ログイン情報と保存URLは機密データとして扱ってください。アプリ独自のパスワード管理・認証状態のエクスポートはありません。URLに含まれるクエリ文字列やトークンは作業セットにも保存されるため、保存前に確認してください。

セッションの初期化はローカルデータの削除です。サーバー側のデータや認証の失効操作は行いません。保存されたCookieの有効期限・サーバー側の失効により、再ログインが必要になる場合があります。

## 検証

```sh
npm run check
npm test
npm run test:e2e
```

E2Eテストは実際のElectronを起動するため、ログイン中のmacOSデスクトップが必要です。外部のサービスにはアクセスせず、ローカルのHTTPサーバーと専用の一時プロファイルを使用します。

生成したアプリに対しても同じE2Eを実行できます（Apple Siliconの例）：

```sh
MSB_EXECUTABLE="$PWD/dist/mac-arm64/Multisession Browser.app/Contents/MacOS/Multisession Browser" npm run test:e2e
```

データ保存先を分けて開発するには：

```sh
MSB_USER_DATA=/tmp/msb-dev-profile npm start
```

## パスキーが要求される場合（Gmailなど）

**現在の未署名ビルドではWebAuthn（パスキー・セキュリティキー）は非対応です。** Ver 0.1.1では要求を待ち続けずに `NotAllowedError` で終了し、画面上に案内を表示します。認証画面の「別の方法を試す」から、パスワードなどの利用可能な方法を選んでください。認証を成功扱いにしたり、二要素認証を迂回したりはしません。

パスキーのみが許可されたアカウントは、このビルドではログインできません。別ブラウザでログインしても、このアプリへCookieが引き継がれるわけではありません。Gmailの実アカウントでの認証完了は未検証です。

ElectronのmacOSネイティブパスキーにはコード署名・provisioning profile・サイトとのAssociated Domains関連付け等が必要です。Gmailなど任意サイトのパスキーをブラウザとして扱うにはAppleのブラウザ向け権限とネイティブ認証連携の設計が必要で、単に設定を有効にするだけでは対応できません。詳しくは [認証対応の制約](docs/authentication.md) を参照してください。

## 対応範囲

一般的なHTTP / HTTPSサイトを対象としています。SSO、外部アプリへの遷移、WebAuthn、クライアント証明書などは対象サイトでの互換性確認が必要です。通常のChromeとの完全な同一動作を保証するものではありません。

初期版ではChrome拡張機能、IDの自動抽出、自動テストの操作UI、テストデータ投入機能、外部ブラウザで開く操作は含みません。
